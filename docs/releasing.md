# Releasing Redrob CAD

How Redrob CAD is versioned, packaged and released.

- **Version:** `[workspace.package] version` in the root `Cargo.toml` is the single source. `cargo xtask version` prints it; `cargo xtask version set X.Y.Z[-pre]` changes it. The app shows it in About, `redrob-cad --version` and `redrob-cad-cli --version`; release builds also embed the commit (`REDROB_CAD_BUILD_SHA`).
- **Cut a release:** cut `release/X.Y.Z` from `develop`, run `cargo xtask version set X.Y.Z` there, open a pull request to `main` and merge it with a merge commit. Tag the merge commit `vX.Y.Z` on `main` and push only the tag; the shared gitflow workflow (`.github/workflows/gitflow.yml`, calling `redrob-labs/.github`) opens the back-merge pull request `main` -> `develop` on its own -- merge it with a merge commit. The tag runs `.github/workflows/release.yml`, which fails if the tag is not the Cargo.toml version, and publishes the GitHub Release `Redrob CAD vX.Y.Z` through the shared `redrob-labs/.github` release-publish workflow (`SHA256SUMS.txt`, `redrob-launcher.json`, published as latest; a version with a pre-release suffix is marked pre-release). Pushing the same tag again is refused once the release is published: bump and tag again. A `workflow_dispatch` run (optionally with `version: X.Y.Z-rc.N`) is a dry run: every job builds and signs and nothing is published.
- **Windows signing:** `packaging/windows/package.ps1` only builds and packages, in three phases (`-BuildOnly` stages the app, CLI and uninstaller executables; `-SkipBuild` builds the MSI and portable zip; `-SetupOnly` wraps the MSI in the branded setup). The workflow signs after each phase with the shared `redrob-labs/.github/actions/sign-windows` action (Azure Artifact Signing over the job's OpenID Connect login, verified with `signtool verify /pa` and the signer's CN), so the portable zip and the MSI carry signed executables, the setup carries a signed MSI, and the setup is signed last.
- **Artifacts:** macOS universal `.dmg` with its branded window (`packaging/macos/dmg/`; Developer ID signed, notarized, stapled) and CLI `.zip`; Windows x64, x86 and arm64 branded `-setup.exe` (per-user, no administrator rights; `packaging/windows/setup/`), the `.msi` it wraps (for managed deployment) and a portable `.zip` (Azure Artifact Signing over OpenID Connect); Linux x86_64 and aarch64 `.AppImage` (+ `.AppImage.zsync` for AppImageUpdate delta updates), `.deb`, `.rpm`, `.tar.gz`; `redrob-cad.png` (the 512 px app icon, named as `icon` by `redrob-launcher.json` so Redrob Launcher's catalog shows this release's logo); `redrob-launcher.json`; `SHA256SUMS.txt`. Windows, macOS and Linux only: the Flatpak, web and FreeBSD release builds were removed on 2026-10-13, and the Flatpak packaging files with them (the web build stays for its own uses).
- **Secrets:** redrob-labs organization secrets. macOS: `APPLE_CODESIGN_CERT_P12_BASE64`, `APPLE_CODESIGN_CERT_PASSWORD` (Developer ID certificate) and `APPLE_NOTARY_API_KEY_P8_BASE64`, `APPLE_NOTARY_API_KEY_ID`, `APPLE_NOTARY_API_ISSUER_ID` (notarization). Windows: Azure Artifact Signing, authenticated with the job's OpenID Connect token (`azure/login`, job `environment: release`, `permissions: id-token: write`) -- the plain IDs `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` and `ARTIFACT_SIGNING_ENDPOINT`, `ARTIFACT_SIGNING_ACCOUNT`, `ARTIFACT_SIGNING_CERT_PROFILE`; no certificate file or client secret anywhere. The login runs after the build and right before signing, because the OIDC token lives minutes. The signer must be the organization's Public Trust certificate (CN=McKinley Rice, Inc.), which the shared action verifies with `signtool verify /pa`. All are optional: a missing set produces unsigned artifacts with a warning.
- **File types:** `.dxf` and `.dwg` (macOS document types, Windows "Open with", Linux MIME types).
- **Local packaging test:** `packaging/macos/package.sh` (ad-hoc signed DMG), `packaging/linux/package.sh`.
